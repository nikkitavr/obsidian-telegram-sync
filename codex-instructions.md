Более четкое описание:
---
Цель. Создать Java‑приложение («Telegram FS Sync»), выполняющее роль телеграм‑бота для приёма сообщений и сохранения их в локальной файловой системе в формате Markdown. Приложение работает автономно (без привязки к Obsidian) и обеспечивает маршрутизацию сообщений согласно настройкам.

1. Функциональные требования
   Подключение бота

Возможность указать bot token, полученный от BotFather.

Хранение токена в конфигурации (при желании можно реализовать шифрование, аналогичное репозиторию).

Обработка сообщений и файлов

Поддержка текстовых сообщений, изображений, документов, голосовых и видеосообщений.

Обработка сообщений из личных чатов, групп, супергрупп и каналов (при условии, что бот добавлен и имеет права).

Создание или дополнение .md‑файлов на основе шаблонов. Формат файлов — Markdown.

Маршрутизация

Гибкая система правил (похожа на messageDistribution из репозитория):

фильтрация по пользователю, чату, топику (при работе в форумах), forwarded‑сообщениям, тексту, дате и др.;

для каждого правила можно задать:

шаблон содержимого (content template);

шаблон пути для заметки;

шаблон пути для файлов;

дополнительные параметры (заголовок, порядок добавления и т. д.).

Обработка множества правил и выбор подходящего для каждого входящего сообщения.

Шаблоны

Поддержка переменных наподобие {{chat:name}}, {{messageDate:YYYYMMDD}}, {{voiceTranscript}} и т. д. (можно частично перенять логику из Template Variables List).

Возможность использовать шаблоны как для содержимого заметки, так и для пути к файлу/заметке.

Хранилище

Выбор корневой папки, в которой будут создаваться заметки и сохраняться файлы.

Создание недостающих папок, проверка уникальности имён файлов (по аналогии с getUniqueFilePath).

Транскрипция голосовых сообщений

По возможности интеграция с MTProto API Telegram (как в репозитории) для расшифровки голосовых и видеосообщений (требует авторизации пользователя и Premium аккаунта).

Альтернативно — использование внешнего сервиса/библиотеки (например, Vosk или Google Speech‑to‑Text), что позволит обойти требования Telegram Premium, но может потребовать конвертацию аудио из OGG/Opus.

CLI/служба

Приложение запускается из командной строки (java -jar / docker image). Чтение конфигурации из YAML/JSON.

Вывод статуса и логов в консоль или файл.

Опционально — возможность работать как системная служба (например, через systemd).

Дополнительные возможности (по желанию)

Удаление обработанных сообщений из Telegram (аналог фичи «Delete processed messages»).

Реакции/ответы бота для отметки «сообщение обработано».

Интеграция с базой данных для хранения журнала (если потребуется).

2. Нефункциональные требования
   Язык: Java 17+.

Сторонние библиотеки:

org.telegram:telegrambots-spring-boot-starter или аналогичный SDK для Telegram Bot API.

библиотека для работы с шаблонами (например, FreeMarker).

библиотека/утилита для транскрипции (при реализации).

Сборка: Maven или Gradle.

Логи: логирование через SLF4J/Logback.

Документация: README с инструкцией запуска и описанием конфигурации, при необходимости — дополнительные файлы (пример конфигурации, перечень переменных и т. д.).
