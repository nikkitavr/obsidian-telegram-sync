Резолюция и основная информация
-----------------------------------------------------------

Цель. Создать Java‑приложение («Telegram FS Sync»), выполняющее роль телеграм‑бота для приёма сообщений и сохранения их в локальной файловой системе в формате Markdown. Является аналогом Obsidian плагина Obsidian Telegram Sync от soberhacker'a, но приложение должно работать автономно (без привязки к Obsidian) и обеспечивать маршрутизацию сообщений согласно настройкам (аналогично).
В корне репозитория есть maven модуль - `my-bot`, в нем ведётся разработка целевого бота. В папке `obsidian-plugin` — исходный код и документация референсного плагина, используем для понимания требований и копирования основной логики.

Программист оставляет //TODO комментарии — их нужно реализовывать либо предлагать альтернативу перед правками. Продолжаем писать код, пока цель проекта и его требования не будут завершены.

Работа уже начата, смотри как `obsidian-plugin` (референс), так и `my-bot` (текущая реализация).

1. Функциональные требования

---

**Подключение и безопасность**

- Возможность указать bot token, полученный от BotFather.
- Хранение токена в конфигурации, ~~поддержка AES-256 шифрования и PIN-кода (см. Bot Token Encryption)~~ (не требуется).

**Обработка сообщений и файлов**

- Поддержка текстовых сообщений, изображений, документов, голосовых и видеосообщений, forwarded, system, топиков, каналов.
- Обработка сообщений из групп, супергрупп и каналов (при наличии прав), в которых есть бот, а так же из личных сообщений в бота.
- Создание или дополнение .md‑файлов на основе шаблонов. Формат файлов — Markdown.
- Скачивание и сохранение файлов, поддержка media group (альбомов). Файлы сохраняются по пути, указанным в конфигурации, но линкуются к соответсвущим .md файлам через формат Obsidian ссылок
- Транскрипция голосовых (интеграция с MTProto или сторонней библиотекой).

**Маршрутизация**

- Гибкая система правил (см. messageDistribution из obsidian-plugin):
  - фильтрация по пользователю, чату, топику, forwarded, тексту, дате, транскрипции и др.
  - поддержка операций: равно, не равно, содержит, не содержит.
  - для каждого правила: шаблон содержимого, шаблон пути для заметки, шаблон пути для файлов, параметры (заголовок, порядок добавления и т.д.).
- Обработка множества правил и выбор подходящего для каждого входящего сообщения.

**Шаблоны**

- Поддержка переменных (см. Template Variables List): {{chat:name}}, {{messageDate:YYYYMMDD}}, {{voiceTranscript}}, {{user:name}}, {{hashtag:[X]}}, {{content:[X-Y]}}, {{replace:...}}, {{file:type}}, {{file:name}}, и др.
- Использование шаблонов для содержимого заметки, пути к файлу/заметке, имени файла.
- Генерация уникальных путей (аналог getUniqueFilePath).

**Файловая система**

- Выбор корневой папки (vaultPath), создание недостающих папок.
- Проверка уникальности имён файлов, корректная работа с вложенными директориями и большими файлами.

**CLI и конфигурация**

- Запуск из командной строки (java -jar / docker image).
- Чтение конфигурации из YAML/JSON (vaultPath, distributionRules, gitAction и др.).
- Валидация конфигурации.

**Логирование и мониторинг**

- Логирование через SLF4J/Logback (файл, консоль).
- (Опционально) логирование в Telegram/внешние системы.

**Дополнительные возможности**

- Реакции/ответы бота для отметки «сообщение обработано» (эмодзи, reply).
- (Опционально) git-автоматизация (pull, commit, push при изменениях vault).

**Особенности для авторизованных пользователей**

- Premium: транскрипция, ускоренная загрузка файлов.

2. Нефункциональные требования

---

- Язык: Java 17+.
- Сборка: Maven.
- Логи: SLF4J/Logback.
- Telegram Bot API: telegrambots-spring-boot-starter или аналогичный SDK.
- Работа с шаблонами: FreeMarker или собственная реализация.
- Транскрипция: интеграция с внешним сервисом или MTProto.

5. Особенности работы с топиками и кастомными названиями (супергруппы)

---

- Для супергрупп (форумов) имя топика по умолчанию берётся как имя группы.
- Для задания кастомного имени топика реализована команда (см. PersonalAssistantBot.java), которая сохраняет соответствие (chat_id, topic_id, title) в embedded базе (сейчас SQLite, таблица group_topics_titles):

  create table group_topics_titles
  (
  chat_id  integer not null,
  topic_id integer not null,
  title    TEXT    not null,
  constraint group_topics_titles_pk
  primary key (chat_id, topic_id)
  );
- При обработке сообщений имя топика подставляется из этой базы (например, как шаблонная переменная {{topicTitle}} или аналог).
- При вызове команды имя топика сохраняется по id чата и id топика, при парсинге сообщения — извлекается по этим id.
