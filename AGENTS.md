Резолюция и основная информация
---

Цель. Создать Java‑приложение («Telegram FS Sync»), выполняющее роль телеграм‑бота для приёма сообщений и сохранения их в локальной файловой системе в формате Markdown. Является аналогом Obsdian плагина Obsidian Telegram Sync от soberhacker'a, но приложение должно работать автономно (без привязки к Obsidian) и обеспечивать маршрутизацию сообщений согласно настройкам (аналогично).
В корне репозитория есть maven модуль - `my-bot`, в нем будет вестись разработка целевого бота. Так же в корне есть папка `obsidian-plugin`, в ней хранится исходный код и документация исходного плагина, можно использовать для понимания требований, а так же копирования основной логики.

1. Функциональные требования
   Подключение бота

Возможность указать bot token, полученный от BotFather.

Хранение токена в конфигурации.

Обработка сообщений и файлов

Поддержка текстовых сообщений, изображений, документов, голосовых и видеосообщений.

Обработка сообщений из личных чатов, групп, супергрупп и каналов (при условии, что бот добавлен и имеет права).

Создание или дополнение .md‑файлов на основе шаблонов. Формат файлов — Markdown.

Маршрутизация

Гибкая система правил (похожа на messageDistribution из obsidian-plugin):

фильтрация по пользователю, чату, топику (при работе в форумах), forwarded‑сообщениям, тексту, дате и др.;

для каждого правила можно задать:

шаблон содержимого (content template);

шаблон пути для заметки;

шаблон пути для файлов;

дополнительные параметры (заголовок, порядок добавления и т. д.).

Обработка множества правил и выбор подходящего для каждого входящего сообщения.

Шаблоны

Поддержка переменных наподобие {{chat:name}}, {{messageDate:YYYYMMDD}}, {{voiceTranscript}} и т. д. (можно перенять логику из Template Variables List в obsidian-plugin).

Возможность использовать шаблоны как для содержимого заметки, так и для пути к файлу/заметке.

Хранилище

Выбор корневой папки, в которой будут создаваться заметки и сохраняться файлы.

Создание недостающих папок, проверка уникальности имён файлов (по аналогии с getUniqueFilePath в obsidian-plugin).

Транскрипция голосовых сообщений

По возможности интеграция с MTProto API Telegram (как в репозитории obsidian-plugin) для расшифровки голосовых и видеосообщений (требует авторизации пользователя и Premium аккаунта. Премиум аккаунт есть, но можно как фоллбэк поддержать сторонюю библиотеку).

Приложение запускается из командной строки (java -jar / docker image). Чтение конфигурации из YAML/JSON.

Вывод статуса и логов в файл, консоль, телеграм, внешнюю систему сбора логов.

Дополнительные возможности (по желанию)

Удаление обработанных сообщений из Telegram (аналог фичи «Delete processed messages» в obsidian-plugin).

Реакции/ответы бота для отметки «сообщение обработано» как в obsidian-plugin.


2. Нефункциональные требования
   Язык: Java 17+.

Сторонние библиотеки:

org.telegram:telegrambots-spring-boot-starter или аналогичный SDK для Telegram Bot API.

библиотека для работы с шаблонами (например, FreeMarker).

библиотека/утилита для транскрипции (при реализации).

Сборка: Maven.

Логи: логирование через SLF4J/Logback.
